# HDL Tools Implementation Plan

> Native execution: implement the tasks in the current checkout and request one
> fresh independent final review. Preserve all existing uncommitted work.

**Goal:** User-facing Yosys checking/synthesis and Icarus checking/simulation,
with a hardened runner shared by DLS export.

**Architecture:** `toolchain.rs` owns processes, source snapshots, scratch
directories and publication. `hdl.rs` owns the new CLI commands. `export.rs`
uses the common execution and I/O helpers. No tools enter the core or HTTP API.

**Tech Stack:** Rust 1.85, Clap, serde_json, libc on Unix, Yosys/ABC, Icarus/VVP.

**Spec:** `docs/superpowers/specs/2026-10-04-hdl-tools-design.md`.

## Global constraints

- Keep seven earlier fixes and DLS export intact; no commit/push requested.
- Source bounds: 8 MiB/file, 32 MiB aggregate, 256 files.
- Output capture: 1 MiB combined; displayed tail 64 KiB.
- Generated files: 32 MiB/file; workspace 128 MiB, 4,096 entries, depth 32.
- Unix virtual memory 2 GiB/process; no core dumps; shared wall/CPU deadline.
- Destinations must be new; no external tools in canonical core/network API.

## Review focus

- Inherited stdout/stderr pipes and background children cannot hang past timeout.
- Tool output floods and artifact growth fail without unbounded parent memory.
- Source FIFOs/devices and generated symlinks are rejected without blocking.
- Shell punctuation in source/include/executable/top paths is never executed.
- Multi-stage jobs share deadlines and never publish failed/partial results.
